## C. 真並行驗證（執行器已備妥，**尚未執行**；等 Codex 核對後由使用者在本機輸入金鑰）
限制：測試庫 MCP 工具依序執行呼叫、`dblink` 需要密碼，無法產生真重疊（已實測），所以改用本機執行器＋HTTP 同時請求。

- 觀測函式：`phase_install_hs_zz.sql`（`zz_hs_call`，只呼叫正式函式；測試庫識別守門、只允許 `CC-EMP-`／`CC-HS-`）；測完 `phase_remove_hs_zz.sql` 移除。
- 自測（不需金鑰，不連網）：`node docs/testdb/hold-settle/run_hold_settle_selftest.js`（33 項：真並行判定 advisory／txid、資料庫不變量、整體判定、缺參數／正式庫網址／非 TTY／金鑰格式的失敗路徑、原始碼保護）。
- 安裝順序（測試庫）：暫裝 06／08／11 實際版本＋本函式（見 README）→ `phase_install_hs_zz.sql` → 使用者執行 `node docs/testdb/hold-settle/run_hold_settle_concurrency.js --env <.env.test> --work <資料夾>`（金鑰只用隱藏輸入）→ 全部拆除並核對基準。
- 案例：
  1. **CC1 重送競爭**（等 advisory 鎖）：同一份確認清單同時送兩次 → 恰一次成功、另一次 already；扣課帳 3 筆（不是 6）。
  2. **CC2 鎖等待期間新增候選**（等預約列鎖）：持鎖者鎖一筆候選並握住；對手執行；握住期間第三個請求新增更近的卡位 → 對手 `CANDIDATES_CHANGED`，沒有任何轉正／取消。
  3. **CC3 鎖等待期間候選被改**：持鎖者改清單內一筆的時間 → 對手 `PLAN_CHANGED`，無任何動作。
  4. **CC4 與櫃檯扣堂／取消競爭**（需階段 08；沒裝會標 `PARTIAL_CC4`，不算完成）：扣堂 → 對手不執行、不重複扣；取消 → 對手 `PLAN_CHANGED`、取消的不被轉正。
  5. **CC5 同會員同票種兩張票同時整理**（等同一把 advisory 鎖）：後到者 `PLAN_CHANGED`，不變量成立。
  每案都要求「真並行證據」（持鎖者在交易內以 pid＋阻擋關係看到對手被擋、案例標記相符、等的是持鎖者的鎖、對手在持鎖者結束後才完成），並在最後檢查全程不變量（每筆綁票恰淨扣 1、取消者無淨扣、餘額＝總堂數−淨扣）。
- 完成標準：`整體判定：HS_CONC_COMPLETE`、資料與登入帳號回到測前基準逐列相同、manifest 完成並封存、報告檔 `hold_settle_conc_report.json` 已保存。

## D. 瀏覽器點擊驗收清單（尚未執行；需測試庫＋本機前端）
1. 櫃檯登入 → 有 5 筆無票待簽約卡位的會員 → 賣一張 3 堂票 → 彈「卡位整理」：轉正 3（日期由近到遠）、取消 2（紅框、列日期）→「先不整理」→ 資料不變 → 再按會員的「轉正簽約」→ 同一畫面 → 「確認整理」→ 結果提示、課表即時更新。
2. 分期票（12 堂開通 4）→ 轉正 4／分期保留 8（不取消）。
3. 尚未啟用票（有效 7 天）卡位跨 12 天 → 窗外標示「不動」。
4. 會員另有同票種舊票 → 超額列「可由其他票券承接，先不動」。
5. 確認畫面開著時，另一個視窗改了其中一堂的時間 → 按確認 → 提示「清單有變動」並重畫。
6. 結果不明分兩種：請求根本沒送達，恢復後重試應首次成功；已提交但回應遺失，重試應 already。兩者分開記錄，不以斷網必回 already 當通過條件。
7. 非櫃檯（教練）登入：看不到「轉正簽約」；直接呼叫 RPC 被擋（NOT_STAFF／NOT_DESK）。
