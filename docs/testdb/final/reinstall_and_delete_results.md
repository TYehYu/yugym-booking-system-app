## 刪除預約後以相同 id 重建
- 流程**允許**（前端有 `dbDel('bookings')`，且 `dbPut` 是 upsert，可用同一 id 再寫入），所以不能靠「流程不允許」帶過。
- **重現**（舊版：觸發器只在 UPDATE 時加版本）：登記操作→刪除預約→相同 id 與內容重建→版本仍是 0；舊扣課請求**成功扣 1 堂**，舊登記請求被接受。
- **修法**：`trg_booking_op_rev_insdel`（AFTER INSERT OR DELETE）也讓版本加 1。實測：刪除前版本 1、重建後 3；舊扣課 `STALE_OP`（淨 0）、舊登記 `REV_MISMATCH`、重建後新的合法操作可扣。

## 08 回復後再次安裝
- 回復檔：刪函式與兩個觸發器、**清空 `ticket_deduct_ops`**（只是操作登記；扣課帳在 `ticket_logs` 不受影響），**保留兩張表**。
- 原先正式庫套用檔的守門會因「表已存在」永遠擋住重裝——已改為只在**函式或觸發器已存在**時停止；表存在不阻擋（`create table if not exists` 沿用）。
- 重裝一併執行 `insert … select id,1 from bookings on conflict do update rev+1`：讓所有既有預約版本前進（沒有計數列者建立為 1）。
- 實測（持久安裝→登記一個操作→回復→回復期間改預約名單與時長→重裝）：守門通過、重裝成功（計數列 58＝預約 58）；回復前登記的舊操作遲到 `UNKNOWN_OP`、淨 0；回復前就在路上的登記請求（帶舊版本 0）`REV_MISMATCH`；重裝後新的合法操作可登記並扣成功。
