## Verified failure mechanisms and change

The existing day view uses a ±3-day booking window. A failed/empty history lookup falls back to that window. With zero remaining unallocated sessions, its latest visible class becomes a false renewal reminder. The existing group fallback always uses the window. The generic ticket lookup also lacks pagination.

A dedicated data-layer reader now pages relevant ticket history (500 rows with exact count) and participant-scoped future group history. Same member/category tickets are included to preserve later-class suppression across tickets. Missing visible bookings, failed/empty lookups, inconsistent counts, truncated pages or duplicate rows invalidate the result. These failures clear reminder maps; they never substitute the display window. Outdated requests cannot overwrite current maps.

The exact failure on the user's device was not observed with browser diagnostics; production data confirms false personal reminders and tests reproduce the window fallback. No claim that a particular HTTP error was observed on her phone.

No booking, ticket, balance, attendance or payment data is changed. No SQL migration.
